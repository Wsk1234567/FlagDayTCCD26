# TCCD · Flag Day 2026

电竞战队风的静态网站：七组销量联赛、F5 特别挑战、共同里程碑、成就墙和活动九条规则。每张贴纸固定 RM5，自愿参与。

Team A 包含第 1–3 组，Team B 包含第 4–7 组。两队总销量由各自小组核实销量自动汇总，不需另填数据；F5 独立，不计入两队成绩。排行榜和战队卡会显示所属队伍。

## 本地查看

无需安装 npm 依赖。使用 Python 3 在此文件夹启动静态服务器：

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8080/`。不要直接双击 HTML：模块和成绩文件需要通过 HTTP 读取。

## 更新成绩

唯一公开数据文件是 `data/event.json`。初始八组都是零，更新时间和截止日期待公布；没有示例或虚构成绩。

| 字段 | 填写方式 |
| --- | --- |
| `updatedAt` | 本次核实成绩的发布时间，例如 `2026-10-06T18:00:00+08:00`。首次发布前保持 `null`。 |
| `deadline` | 你指定的交接截止日期时间，必须包含时区。未公布时保持 `null`。不会自动采用官方活动结束日期。 |
| `status` | 活动期间为 `live`；结赛请使用下方命令生成快照。 |
| `groups[].id` | 固定为 `1` 至 `7` 及 `f5`，不可删除或重复。 |
| `groups[].name` | 可改队名，最多 40 个字符。不要填写成员个人资料。 |
| `groups[].verifiedSold` | **累计**已核实销量，非负整数；不是本次新增数量，也不是领取数量。 |
| `groups[].treasuryReceived` | 财政确认已收到的**累计** RM 金额，填数字，不写 `RM`。不包含其他捐款；不得超过该组核实销量 × RM5。 |
| `groups[].handoffComplete` | 负责人确认钱、剩余贴纸、记录已全部交齐后设为 `true`。财政钱款也必须收齐。其余时间为 `false`。 |
| `finalSnapshot` | 结赛命令生成的快照；日常更新不修改它。 |

例如第 1 组累计核实 20 张，财政暂收到 RM50：

```json
{ "id": "1", "name": "第 1 组", "verifiedSold": 20, "treasuryReceived": 50, "handoffComplete": false }
```

网站显示 20 张、对应 RM100、财政已收 RM50。随后交财政时，把 `treasuryReceived` 改为 100，销量仍为 20。继续售出并核实 5 张时，累计销量才改为 25。

普通组以 LC 当面点清收款、核对记录后的销量上榜。F5 也只发布核实后的销量，交接由 Cadet Leader 直接交财政。网站不取代 Excel 和双方正式交接记录。

发现记录错误时，更正累计数字与更新时间。若销售金额减少，应一起核对财政已收金额与交接状态；有差异先向上一级 NCO 报告，不把差额随意改成零。主动报告问题或投诉不触发积分处罚。

在提交前运行（需要 Node.js 18 或以上）：

```powershell
node tools/manage-event.mjs validate
node --test tests/league.test.js
```

有错误时修正数据后再提交；网站遇到无效数据会显示错误和 `—`，不会假装所有组都是零。

## 排名和成就

- 第 1–7 组按累计销量降序，同分并列，使用竞赛排名（例如 1、1、3）。同分显示时按组号排序，不作为额外胜负条件。
- “距上一名”是与最近一个严格更高销量档的差值。同销量组不会相互显示差距。零销量仍可并列，但不显示前三名奖牌或认定冠军。
- F5 不进入排名，贡献计入全团销量与财政金额。
- 每组 10／25／50／100 张分别解锁四个销量成就；完整交接另获一个成就。更正数字后，未达到的成就会恢复为未解锁。
- 全团每累计 100 张解锁一站；例如 100 张时，显示已解锁 1 站，下一站 200 张，下一站进度从 0% 开始。
- 活动期间的榜首只是当前领先，冠军在结赛确认后显示；并列榜首共同获得冠军。零销量结赛不产生冠军。

## 确认结赛并锁定最终成绩

负责人先完成最后核对，更新成绩和 `updatedAt`，再运行：

```powershell
node tools/manage-event.mjs finalize
```

命令将状态改为 `final`，复制八组成绩及截止日期到 `finalSnapshot` 并记录确认时间。网站的排名、金额、成就和日期都使用该快照。之后修改普通 `groups` 不会改变最终展示，重复运行命令也不会覆盖快照。查看生成内容后提交并发布。

若最终成绩有确实需要纠正的错误，由负责人审核后同时将 `status` 改回 `live`、`finalSnapshot` 改为 `null`，更正 `groups` 和 `updatedAt`，再运行结赛命令并发布。Git 提交记录保留更正过程。不要在普通每日更新时这样操作。

## 发布到 GitHub Pages

1. 创建 GitHub 仓库，将此文件夹的项目文件上传至 `main` 分支，包括隐藏目录 `.github` 下的 workflow。只上传网站项目，不上传原始 Excel、PDF、个人资料或财务明细。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 在 **Actions** 页面运行 **Publish Flag Day website**，或向 `main` 提交修改自动触发。
4. 工作流先校验数据并运行测试，通过后发布。打开部署结果中的 Pages URL，分享该网址即可。

发布流程只打包 HTML、CSS、JS、徽章和公开成绩 JSON，不打包工具、测试或 README。若使用其他默认分支，需要对应修改 workflow 的 `branches`。

所有公开文件和 Git 历史都可以被访客读取。仓库和成绩 JSON 不应包含姓名名单、联系方式、逐笔钱款记录或密钥。原始文件应继续放在私下的记录系统中。

## 界面和故障检查

检查桌面及 320／390px 手机宽度、展开战队成就、键盘导航、减少动态效果设置。成绩文件缺失、JSON 格式错误、无效数值或读取超时会显示明确提示及重新加载按钮，规则仍可阅读。时间统一显示为马来西亚时间。

本项目没有账户、在线支付、后台数据库或追踪代码；需要更新时由负责人修改公开数据并提交 GitHub。初始截止日期待公布，最终冠军待结赛确认。
